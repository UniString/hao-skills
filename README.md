# hao-skills

我个人的 AI 助手 skill 仓库。把日常在用的 skill 集中放一处，换机器或者换工具时直接取。

## 什么是 skill

skill（直译"技能"）是一份写给 AI 助手看的说明书。助手读到这份文件之后，后面回答就按里面写的规矩来。它本身只是 markdown 文本，没有代码，也不用装依赖。

## 仓库结构

一个 skill 一个目录，目录名就是 skill 的名字，入口固定是目录下的 `SKILL.md`。

`SKILL.md` 开头要写两个字段：`name` 是名字，`description` 是一句话说明这个 skill 什么时候该用。助手平时不会把所有 skill 都读一遍，它是靠 `description` 判断这次要不要加载。

目前收录 2 个，是一对：

| 目录 | 什么时候用 |
| --- | --- |
| `plain-chinese-chat/` | 助手用中文跟你对话时：解释概念、汇报进展、教你怎么配置或审批一件事 |
| `plain-chinese-docs/` | 助手写或改中文技术文档时：README、设计说明、变更记录、调研笔记这类给人看的 markdown |

两个解决的是同一个问题：助手的默认输出爱堆名词、中英夹杂，读的人得自己补背景才知道它在说什么。区别只在场景——聊天里话要短，文档里要能脱离上下文独立读懂。

## 怎么用

1. 把要用的目录整个复制到助手读 skill 的位置。
2. 新开一个对话，助手就会读到。

以 ZCode 为例，位置有两个：

- 只给一个项目用：项目目录下的 `.zcode/skills/`
- 给这台机器上所有项目用：`C:\Users\<你的用户名>\.agents\skills\`，Linux 和 macOS 上是 `~/.agents/skills/`

换别的工具，目录位置不一样，查它自己的文档。

## 怎么加新的

1. 建一个目录，名字用小写加连字符，比如 `review-checklist/`。
2. 目录里放 `SKILL.md`，开头写 `name` 和 `description`。`description` 写"什么时候用"，不要写"这个 skill 讲了什么"——前者决定助手会不会加载它。
3. 在上面那张表里加一行，写清它什么时候用。
4. 提交推送。
